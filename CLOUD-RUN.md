# Облачные запуски LifeMart

Ежедневный боевой исполнитель `LifeMart production pass` работает на сервере GitHub,
независимо от компьютера, приложения Codex и этого чата.

| Екатеринбург | Слоты отправки | Cron UTC |
|---|---|---|
| 08:30 | 09:00, 10:00 | `30 3 * * *` |
| 10:30 | 11:00, 12:00, 13:00 | `30 5 * * *` |
| 14:00 | 15:00, 16:00 | `0 9 * * *` |

Все три расписания ежедневные, включая выходные. На событии `schedule` автоматически
выбираются нужные слоты и режим `apply`. Ручной запуск по умолчанию остаётся `preview`.
Последовательность АВ12 → М42 → Г34; одновременные боевые проходы запрещены concurrency.
Локальный исполнитель должен оставаться отключённым. Журнал и ошибки доступны в
[GitHub Actions](https://github.com/SergeyMartynov96/JmRabotaOblako/actions/workflows/cloud-production.yml).

GitHub не гарантирует точность времени cron. Если задание опоздало до первого слота
отправки, оно завершается ошибкой и требует сверки истории СУ; отсутствие ожидающих
карточек после опоздания не маскируется успешным пустым проходом. До дедлайна пустое
ежедневное окно считается штатным отсутствием работы. При частичном сбое сохранённые
отпечатки защищают уже изменённые карточки от нового сокращения при повторе.
Первое фактическое срабатывание ежедневного расписания ещё предстоит проверить.

## Предыдущий разовый тест чтения

GitHub Actions также содержит `LifeMart cloud read-only test` для проверки чтения.
Первый тест назначен на **8 ноября 2026 года, 14:00 по Екатеринбургу**
(09:00 UTC). GitHub может задержать старт; это не система с гарантией точного времени.
Проверка даты исключает рабочие запуски этого расписания в последующие годы.

Задание доступно также вручную в GitHub → Actions → LifeMart cloud read-only test → Run workflow.
Параметр `slots` задаёт время отправки заявок по Екатеринбургу; для теста 14:00 — `15:00,16:00`.

Задание входит в СУ, проверяет доступ к трём филиалам и таблицам, читает актуальные
заявки, оформленные в день запуска, и сверяет суммы карточек с таблицами по дате привоза.
Карточки поставщиков вне заголовков таблицы не открываются. Неоднозначные соответствия
пропускаются. Если отчёт требует пагинации, проверка завершается ошибкой вместо
выдачи частичного результата. Если подходящих карточек нет, функциональный тест
не считается пройденным. Уже отправленные заявки это задание не восстанавливает:
при задержке старта за время отправки нужна отдельная сверка истории.

**Это тест чтения и расчёта текущих сумм, а не боевой алгоритм корректировки.**
CSV не различает формулы плана и факты: исходный план до прежних правок не восстанавливается.
Скрипт не меняет заявки, таблицы или расписания СУ. Публикация среды Codex для этого
задания не нужна.

Учётные данные берутся из `LIFEMART_LOGIN` и `LIFEMART_PASSWORD`, если заданы оба
GitHub Actions secrets; иначе — из уже выбранного владельцем файла `AGENTS.md`.
Секретные значения не включены в скрипт и маскируются перед сетевыми запросами.
В общедоступный журнал выводятся только результаты доступа и количество проверенных
и пропущенных заявок, без финансовых сумм, ID заявок и имён поставщиков.

Локальная проверка:

```sh
python3 -m unittest discover -s tests -v
python3 scripts/cloud_readonly_test.py --slots '15:00,16:00'
```

Для подробного локального отчёта можно передать `--report /tmp/lifemart-check.json`.
Он содержит рабочие данные: не добавлять его в Git или общедоступные артефакты Actions.
Пакеты сторонних библиотек не требуются; используются Python 3.9+ и системная проверка TLS.


## Боевой исполнитель

`LifeMart production pass` (`.github/workflows/cloud-production.yml`) запускается
ежедневно по расписанию выше и вручную через GitHub Actions. `operation=preview` выполняет полный расчёт без
сохранения; `operation=apply` повторяет расчёт, сохраняет контрольные отпечатки
и только затем применяет изменения. Слоты задаются параметром `slots` по Екатеринбургу.
Ежедневное расписание включено; `scripts/cloud_schedule.py` выбирает слоты по cron-событию.
Локальный исполнитель остаётся отключённым.

Порядок АВ12 → М42 → Г34. АВ12 переносит факты без изменения заявок.
М42 и Г34 читают плановую формулу и рассчитанное значение из одного листа,
учитывают топы, исходные количества, кратность и минимумы. Уже записанное число
принимается как факт только при совпадении с полным итогом карточек.
Количество 1 и 2 сохраняется; при недостижимой цели ассортимент не обнуляется.
Г34 контролируется по независимой сумме поставщиков с пределом 60 000 ₽;
мягкий ориентир М42 допускает превышение до 2 000 ₽ согласно §6 регламента.
Табличные дневные итоговые формулы сохраняются.

Перед сохранением проверяются все актуальные заявки поставщика по дате привоза,
включая отправленные; изменяются только ожидающие заявки выбранных слотов.
Смена состава группы, неоднозначная ячейка, неизвестная форма, изменившаяся карточка,
пагинация или отсутствие подтверждённого плана останавливают зависимую операцию.
После второго шага сохранения карточка перечитывается, и только подтверждённый
агрегированный факт записывается в исходную ячейку. Запись проверяется через CSV
и строку формул. В публичный журнал не выводятся суммы, поставщики или ID карточек.

До изменений Actions сохраняет артефакт `lifemart-journal-<run_id>` с SHA-256
отпечатками исходных и желаемых карточек, без количеств, цен и сумм. Полный
рабочий план остаётся временным файлом runner и удаляется при завершении. При
повторном запуске прежние отпечатки загружаются: сохранённая карточка не сокращается
повторно, после сбоя записи таблицы повторяется перенос. Если состояние не совпадает
ни с исходным, ни с ожидаемым, требуется отдельная сверка. Артефакты хранятся 90 дней.
Обычный повтор выполняется новым `Run workflow`, а не перезапуском только последнего
шага; два боевых задания одновременно не выполняются. При частичном сбое сначала
сверить сохранённые карточки и ячейки, затем запускать оставшееся окно.

Проверка 08.11.2026: [предварительный проход](https://github.com/SergeyMartynov96/JmRabotaOblako/actions/runs/42466944724)
и [боевой проход](https://github.com/SergeyMartynov96/JmRabotaOblako/actions/runs/42467181066)
успешны. Окно 15:00/16:00: подтверждены 5 фактических ячеек, изменена одна заявка
М42; АВ12 и Г34 перенесены без изменения количеств. Пропусков поставщиков в этом
окне не было. Это проверка данного окна, а не подтверждение ежедневного расписания.

[Повторный расчёт после боевого прохода](https://github.com/SergeyMartynov96/JmRabotaOblako/actions/runs/42467478725)
успешно загрузил контрольный журнал и предложил **0 изменений** по всем филиалам.
Пять фактических ячеек дополнительно сверены независимым HTTPS-чтением СУ и CSV.
