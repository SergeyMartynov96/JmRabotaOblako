# Утренние показатели

Отдельный модуль; не импортирует и не запускает код заявок. Работает только через
GitHub Actions. Доступы СУ — только Secrets `LIFEMART_LOGIN`/`LIFEMART_PASSWORD`;
чтение пароля из файлов запрещено. Закупочные листы и таблицы топов доступны ему только для чтения.
Пишет только восемь согласованных ячеек в блоке текущей недели «Выручки» каждого
филиала: выручка сверху/снизу, сумма списаний, общий % снизу, три топа, закуп факт.
Не создаёт даты/недели, не меняет планы, оформление, формулы или прочие показатели.

Каждый запуск обрабатывает только вчера по Asia/Yekaterinburg. Дату задним числом
указать нельзя. Запуск, созданный в другой календарный день, отклоняется. Заполненная
ячейка (включая 0, прочерк и формулу) сохраняется; повторный запуск её не обновляет.
Перед записью проверяются полная дата, недельный заголовок и дата нижнего блока,
а затем пустота самой ячейки. Значение вставляется целиком через clipboard:
посимвольный ввод процентов может дать двойной знак %. Запись перечитывается через
формульную строку и сравнивается численно с учётом процентного масштаба.
Для базовых показателей вход в СУ выполняется только при чтении нужного отчёта.
BI-сессия подготавливается до открытия редакторов Sheets. Причины читаются также
для проверки согласованного объединения «Порча + Брак». Недоступность BI не блокирует
остальные источники; ошибка фиксируется без подстановки нулей.

Источники:

- СУ, отчёт по выручке, сутки, вчера–вчера, бренд Все; точное название филиала,
  строка «Итоговая выручка», колонка «Итоги». Параметр выбора `department[]`.
  Один общий отчёт по трём магазинам, ожидание до 10 минут без повторного запроса.
- СУ, отчёт по актам списания, вчера–вчера, один филиал, без ограничений статуса/
  причины; сумма себестоимости документов. Этот отчёт принимает фильтры GET,
  несмотря на POST в HTML формы. Дублировать footer в сумму нельзя.
- Топы: актуальная вкладка, три блока сверху вниз — готовая, десерты, Япония.
  Вторая колонка нужной даты, исходный итог наличия снизу; результат 100 − итог.
  Если все продуктовые ячейки пустые, результат «—», даже если формула итога 0.
  Явные нули → 100 отсутствия. У АВ12 общий заголовок дат для всех блоков.
- Закупочные листы: итог еды + Японии вчерашней даты. Десерты исключены.
  Г34 подписывает итог «СУММА ГОТОВАЯ+ЯПОНИЯ», М42 — «Итого готовая еда».
- Суммы округляются до рубля HALF_UP. % списаний берётся из видимого результата
  существующей верхней формулы, с её точностью; М42 внизу имеет процентный формат,
  АВ12/Г34 — число процентных пунктов. Формулы не заменяются.

Пустой корректный отчёт/нет даты источника/незаполненные топы → «—», без ошибки и
письма, без последующих догрузок. Сбой входа/сети/структуры/даты назначения/записи →
ошибка Actions и штатное уведомление GitHub о сбое. Остальные доступные показатели
и филиалы обрабатываются. Успешных писем модуль не отправляет.

Ручная проверка: workflow `daily-metrics.yml`, operation=preview, branch=М42/all.
Preview ничего не пишет. Apply разрешён только для вчерашней даты текущего запуска.
В журнале только счётчики/причины ошибок; суммы и исходные документы не публикуются.
Расписание включено после облачной проверки: cron-job.org job 8893983, ежедневно
08:00 Asia/Yekaterinburg, один dispatch apply/all, без повторов и native cron.
Первое автоматическое заполнение назначено на 19.11.2026 за 18.11.2026.
Исполнитель использует установленный в GitHub Chrome, локальный запуск выключен.

УВ, OSA, накладные и причины обрабатываются в том же модуле, после основных
показателей. Код автоматизации заявок не изменяется.

Дополнительные согласованные источники:

- УВ: «Упущенная выручка. Период. Магазины. % (мета) 2.0», процент от общей
  выручки за вчера, выбранный филиал; недельный итог не использовать.
- OSA 20:00: «OSA % по in_stock Готовая еда + Япония», серия «На 20:00», вчера.
- По накладным: дата прихода вчера, именно подразделение получения товара
  (`Waybill[recipient_id][]`), сумма с НДС по общему списку 23 точных
  контрагентов; остальные варианты контрагентов не включаются автоматически.
- Причины: «Списания. Причины. Период, %» за вчера; перенос в оба нижних блока,
  включая ротацию, товарооборот, минимальную сумму, ручное, минимальные остатки
  и поставщика. Отсутствующая причина оставляет ячейку нетронутой. Явный ноль
  в корректном отчёте переносится как ноль. Причины не объединяются с «СГ закуп».
- Проценты внутри модуля единообразно представлены процентными пунктами.
  При записи сохраняется принятый формат листа: М42 — процент, АВ12/Г34 — число.
  Уже заполненные значения и формулы не заменяются.

BI читает сохранённые query_context и параметры конкретных графиков (3770/3696/4412).
Вход accounting выполняется в Chrome с cookies СУ; ожидание ограничено тремя
минутами до появления CSRF-токена, без ожидания отрисовки дашборда. Каждый запрос
данных также ограничен 180 секундами. Запросы имеют точный диапазон вчера–сегодня
(правая граница исключена), гранулярность день и один выбранный филиал. Для OSA
запрашивается только серия на 20:00; бизнес-фильтры сохранённого графика остаются.
Ошибки источников не дают нулей/замен в дополнительных ячейках и отмечаются в Actions.
Одна и та же неудачная авторизация/загрузка внутри прохода не повторяется.

По решению владельца «Брак» включается в «Порча»: проценты этих двух причин
за один день складываются до округления. Разрешено исправить уже заполненную
«Порча» только при точном совпадении с отдельной «Порча» того же отчёта; даты,
пустота/исходное значение и итог записи проверяются. Формулы и произвольные ручные
значения не заменяются.
Неизвестные новые причины требуют явного сопоставления, а не приблизительного поиска.

Дата с полным годом и недельные/нижние даты дополнительно проверяются напрямую
через одноклеточные native-значения Sheets (GViz), без зависимости от отставания
формульной строки редактора. Внутри этих проверок короткое отображение «18.11»
сохраняет полный год из Date(year, month, day). Пустота/формулы целевых ячеек
проверяются независимыми устойчивыми чтениями редактора, а запись перечитывается.
